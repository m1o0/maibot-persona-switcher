## 它解决什么

调人设的人都遇到过这两件事：

**一、改完忘了原文。** 想试试「冷面助手」的风格，把 `group_chat_prompt` 整段换掉，聊了两天觉得还是原来那版好——然后发现原文没存，只能凭记忆往回拼。

**二、试用的风格忘了换回来。** 想让麦麦今晚换个语气陪人聊天，第二天忘了改回去，一周后才发现群里那个说话的人已经不是她了。

这个插件就干这两件事：**把当前人设存下来随时换回**，以及**给切换设个时限，到点自动恢复**。

对使用者来说，人设切换只有两种状态：要么是你选的那份，要么是原来的。不会出现「我以为在用它，其实早就被改掉了」。

## 快速开始

1. 把本目录放进 `MaiBot/plugins/`（目录名随意，建议 `m1o0_persona-switcher`）
2. 重启 MaiBot，或等插件热重载
3. 打开 WebUI，顶栏会多出「人设存档与切换」标签

页面进去第一件事：**在「整套人设」页存一份当前状态的存档**，名字随便，比如「原始版」。这是你的安全绳。

之后想换风格就存新的、应用新的；想换回来就点原来那份的「应用」。

## 三级粒度

MaiBot 的人设分布在三个层级，这个插件按同样的三层来切：

| 范围 | 备份的字段 | 典型用途 |
|---|---|---|
| **整套人设** | `bot.nickname`、`bot.alias_names`、`personality.personality` / `behavior_style` / `reply_style` / `multiple_reply_style` / `multiple_probability`、`chat.reply_style.group_chat_prompt` / `private_chat_prompts`、以及**全部**聊天流的专属提示词 | 换一个完整的角色 |
| **群聊人设** | 只备份 `chat.reply_style.group_chat_prompt` | 所有群统一换个说话风格，但人格和私聊不动 |
| **聊天流人设** | 只备份某个会话在 `chat.reply_style.chat_prompts` 里的那一条 | 只让某一个群变成另一种风格，别的群照旧 |

聊天流那一页会列出你所有的群和私聊，并标出哪些已经有专属提示词。

> 只动人设字段。聊天频率、模型、语音、黑白名单、广告词……一律不碰。这是硬约束，不是「尽量不碰」。

## 限时生效

每份存档的应用区有个下拉框：

```
永久生效
15 分钟后恢复
30 分钟后恢复
1 小时后恢复
3 小时后恢复
8 小时后恢复
```

选好时长再点「应用」，插件会在应用前先把当前人设存一份自动备份，然后记录「到什么时间点该恢复」，由后台任务到点切回。

场景举例：

- 今晚想让她用温柔语气陪人聊，选「3 小时后恢复」——第二天醒来群里那个人已经恢复正常了
- 想跟朋友演示「麦麦换个性格」，选「15 分钟后恢复」，不用记着手动改回来

页面顶部常驻一条状态栏，随时能看到还剩多久：

```
正在使用存档 温柔版（整套人设）· 还剩 28 分钟 自动恢复
```

限时的时候会多出「取消限时」按钮（把当前这份改成永久），有备份时还会多出「立刻恢复原人设」。

### 关于「立刻恢复」

应用任何存档时，只要线上内容和存档不一样，插件就会先把你**原来的**相关字段存成 `_应用前自动备份_<时间戳>`。

「立刻恢复原人设」就是切回这一份。所以：

- 存档列表里那些 `_应用前自动备份_` 开头的条目**别急着删**，它们是退路
- 如果你手动改过 `bot_config.toml`，状态栏会提示「线上人设与这份存档已不一致」

### 重启之后

限时状态是持久化的。插件重载或 MaiBot 重启后：

- 还没到点 → 重新挂起定时任务，接着等
- 已经过了点 → 默认立刻恢复（`on_restart = "restore"`）；改成 `keep` 则保持现状
- 不想用限时功能 → 把 `[auto_restore] enabled` 设为 `false`，此时就算调用方传了时长也不生效

## 配置

```toml
[plugin]
enabled = true
config_version = "1.1.0"

[auto_restore]
# 是否允许限时生效。关掉后只能手动切回。
enabled = true
# 应用存档时不填时长就用这个值。0 = 不自动恢复（永久生效）。
default_minutes = 0
# 插件重启后发现限时已过点时的做法：
#   restore - 立刻恢复原人设（默认）
#   keep    - 保持现状，只在界面上提示
on_restart = "restore"
```

应用存档时页面上的时长选择默认会跟随 `default_minutes`（若该值在下拉框选项里）。

## 数据放在哪

```
plugins/<插件目录>/
├── archives/                 ← 人设存档，一份一个目录
│   └── 温柔版/
│       ├── persona.json      实际人设内容
│       └── meta.json         保存时间、备注、范围、摘要
└── active_state.json         ← 当前生效状态（哪份存档、何时到期）
```

`archives/` 和 `active_state.json` 都在 `.gitignore` 里——里面是你的聊天流 ID 和实际人设内容，别提交到公开仓库。

删掉 `active_state.json` 相当于「忘掉正在用哪份存档」，线上人设不受影响。

## 安全性

插件会直接读写 `MaiBot/config/bot_config.toml`，因为宿主没有提供写主配置的能力（只有 `config.get` 之类的只读能力）。这意味着：

- 插件拥有和你相同的配置文件权限，请只安装你信任来源的插件
- 写盘前会用 `tomllib` 解析一遍，坏内容不会落盘
- 走 `tomlkit` 而不是字符串替换，保留原有注释和排版
- 只碰上面列出的那些人设字段，其余内容原样保留
- 依赖 `tomlkit >= 0.12`，已在 `_manifest.json` 的 `dependencies` 里声明；宿主环境通常已自带

## 常见问题

**Q：应用存档后需要重启吗？**
不用。MaiBot 会监视 `bot_config.toml` 并自动热重载（几秒内）。

**Q：能只改某个群的语气，不动别的群吗？**
用「聊天流人设」那一页。选群 → 编辑专属提示词 → 保存到线上。或者把它存成存档，以后一键切换。

**Q：存档会跟着插件升级丢吗？**
不会。`archives/` 在插件目录下，升级插件不影响；但如果换机器或重装，记得自己备份这个目录。

**Q：为什么我的「立刻恢复原人设」按钮不见了？**
说明当前没有生效的存档，或者那份存档应用时线上内容和存档完全一致（等于没切换，也就没有备份）。状态栏会显示「当前生效的是**线上原始人设**」。

**Q：限时到了但没恢复？**
先看状态栏是不是还在倒计时。如果插件在到点前被禁用过，重新启用时会读状态文件补上（除非 `on_restart = "keep"`）。真出问题可以点「立刻恢复原人设」手动切回。

## 与别的插件的关系

这个插件只写 `bot_config.toml`，不改运行时的提示词注入。如果你还装了改写 system prompt 的插件（比如按概率替换人格的那类），两者会叠加生效——它们作用在请求阶段，这个插件作用在配置阶段。

想避免互相干扰，建议同一时间只启用一种切换机制。
